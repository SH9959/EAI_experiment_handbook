# 助教：课堂协助与验收

这里不额外创造教材之外的评分比例，只把教材实验中的**可观察结果**整理成验收点，便于课堂快速确认学生是否真正完成。

## 第 3 章

### 人机对话

学生应能展示至少一条完整链路：

```text
用户输入 → 模型处理 → 有意义的回答
```

扩展实验中再检查：

- 图片输入是否真的参与了回答；
- SenseVoice 输出是否与语音内容基本一致；
- TTS 是否生成并播放模型回答。

### AnyGrasp

仿真验收优先看：

- 点云是否正确；
- 是否存在合理抓取候选；
- 抓取位姿坐标系是否转换正确；
- 方块是否真正被夹起。

实机不要只看“偶然成功一次”，还要确认执行过程没有明显的奇异姿态或碰撞风险。

## 第 4 章

### ALFWorld / ALFRED

ALFWorld 直接观察任务是否完成；ALFRED 要让学生解释 SR、GC、PLW SR、PLW GC，且能说明一次失败原因。

### AI2THOR

重点查看完整历史：

```text
当前观察 → 模型动作 → 环境执行结果 → 下一步规划
```

如果失败，学生应能指出是“规划错误”“动作不合法”还是“动作合法但环境执行失败”。

### 方块重排 / 汉诺塔

先验收规划，再验收机器人执行。尤其汉诺塔，要检查每一步结构化动作是否符合规则，不能只看最后结果。

## 第 5 章 ACT

仿真部分至少检查：

- 数据采集文件存在；
- `visualize_episodes.py` 能正确显示；
- 训练产生 loss 曲线和 checkpoint；
- `--eval` 时能看到 rollout 结果。

实机部分至少检查：

- 采集数据包含三路相机与关节状态；
- 模型训练使用的正是该数据目录；
- 推理时由模型控制从臂，而不是主臂遥操作。
